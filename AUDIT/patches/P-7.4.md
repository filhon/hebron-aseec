# Patch — P-7.4 (Formulários Flats)

**Motivo:** CS-9 — o wizard coleta documento de identidade, CPF/nascimento de acompanhantes e
critérios de scoring que incluem **saúde autodeclarada** (BRAIN §6.8 critério d — dado sensível,
LGPD art. 5º II) sem nenhum step de consentimento; upload de documento sem bucket definido
(P-0.12); D-5 — checklist de inventário no check-in descartado (BRAIN §6.8: check-in presencial na
recepção; o sistema registra a transição, não o inventário).
**Pré-requisitos novos:** P-0.12 (bucket `flats-documentos`), P-0.13 (consents).

---

## Escopo

### ANTES

```
Formulários: reserva completa multi-step (dados do responsável com upload de documento →
acompanhantes com CPF e data nascimento → veículo → 3 períodos de preferência → critérios de
scoring → ajuda de custo opcional → revisão). Aprovação (selecionar período final, observações).
Check-in (checklist de inventário).
```

### DEPOIS

```
Formulários: reserva completa multi-step (CONSENTIMENTO LGPD → dados do responsável com upload de
documento para o bucket flats-documentos → acompanhantes com CPF e data de nascimento → veículo →
3 períodos de preferência → critérios de scoring → ajuda de custo opcional → revisão).

Step de consentimento (novo, primeiro step): finalidades granulares — processamento dos dados da
reserva (obrigatório para prosseguir), dado de saúde autodeclarado do critério d (consentimento
específico e destacado; o campo de saúde só aparece se consentido; sem laudo, sem detalhe clínico —
apenas sim/não conforme BRAIN §6.8), comunicação por email sobre a reserva (transacional, informativo).
Grava em public.consents (P-0.13).

Aprovação (selecionar período final, observações). Check-in/check-out: registro simples de
transição com data/hora e observações — SEM checklist de inventário (decisão D-5; BRAIN §6.8:
check-in é presencial na recepção).
```
