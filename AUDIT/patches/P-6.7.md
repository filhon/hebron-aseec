# Patch — P-6.7 (RLS Policies Plataforma)

**Motivo:** o critério "Aula locked: não visível se anterior não concluída" via RLS exige checar,
por linha, a conclusão da aula anterior do mesmo curso pelo usuário — um executor literal (G1) vai
escrever subquery correlata frágil ou desistir e marcar [x]. Especificar o mecanismo (helper
`SECURITY DEFINER`, mesmo padrão de `has_role`/`has_designation`) fecha a ambiguidade. Também:
CS-3 (número — ver `migracoes-numeracao.md`).

---

## Escopo

### ANTES (trecho)

```
RLS para schema plataforma. Qualquer usuário autenticado: SELECT em courses publicados, lessons de
cursos matriculados. Progresso e notas: apenas próprios. Super_admin e instrutor: CRUD completo.
Certificados: SELECT próprio + verificação pública por hash.
```

### DEPOIS

```
RLS para schema plataforma. Qualquer usuário autenticado: SELECT em courses publicados; lessons de
cursos matriculados. Trilha sequencial: criar função helper
plataforma.can_access_lesson(user_id, lesson_id) — SECURITY DEFINER STABLE, mesmo padrão de
has_role — que retorna true se a aula é a primeira do curso ou se a aula anterior (por module/order)
tem progress.completed_at do usuário; a policy de SELECT em lessons usa o helper (evitar subquery
correlata inline). Progresso e notas: apenas próprios. Super_admin e instrutor: CRUD completo.
Certificados: SELECT próprio; verificação pública por hash via rota que consulta apenas
(hash → curso, nome, data) — não abrir SELECT anon na tabela.
```

## Critérios de aceite

### ANTES

```
- [ ] Aula locked: não visível se anterior não concluída (trilha sequencial)
```

### DEPOIS

```
- [ ] Helper can_access_lesson criado (SECURITY DEFINER STABLE) e usado pela policy de lessons
- [ ] Aula N inacessível com aula N-1 incompleta; acessível após concluir (teste com 2 usuários)
- [ ] Verificação pública de certificado expõe somente curso/nome/data via hash (teste)
```

Arquivos permitidos: trocar número fixo pela convenção de G6.4 (SQL de policies pós-migration do kit).
