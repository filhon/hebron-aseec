# Patch — P-9.2 (LGPD Audit) — REESCRITA

**Motivo:** a fundação LGPD sobe para P-0.13 (decisão Fase 3 Q5 — antes dos módulos que coletam
mais PII), e a direção sobre exclusão foi dada na Fase 1 Q4 ("mude o BRAIN para atender o direito
de exclusão em qualquer dado exigido por lei"). P-9.2 deixa de criar o schema de consentimento
(já existirá) e vira: superfícies de titular ("Meus Dados"), export, fluxo de exclusão fim-a-fim e
revisão final de compliance.

---

## Escopo

### ANTES

```
Implementar compliance LGPD. Tela "Meus Dados" em cada app: visualizar, exportar (JSON + CSV),
solicitar exclusão. Consentimento granular no cadastro (newsletter, marketing, compartilhamento).
Política de retenção configurável por tipo de dado. Log de acesso a dados pessoais. Revisão de
todos os dados pessoais armazenados (CPF, documentos, fotos) para verificar criptografia e acesso
adequado.
```

### DEPOIS

```
Compliance LGPD — superfícies de titular e revisão final (a fundação — public.consents, fluxo de
anonimização, política de PII em audit diffs, retenção — existe desde P-0.13; o consentimento no
cadastro existe desde P-1.26/P-7.4; este prompt NÃO recria nada disso).

Tela "Meus Dados" (componente compartilhado em packages/ui, montado em cada app): visualizar dados
armazenados e consentimentos, revogar consentimento por finalidade, exportar (JSON + CSV),
solicitar exclusão. Solicitação de exclusão: gera ticket para super_admin; a execução usa o fluxo
de anonimização de P-0.13 — exclusão/anonimização REAL dos dados pessoais onde a lei exige,
preservando registros contábeis/deliberativos pseudonimizados (BRAIN §9 emendado — decisão F1-Q4).
Log de acesso a dados pessoais (leituras de CPF/documentos por admin ficam auditadas). Revisão
final: varredura de todos os dados pessoais (CPF, documentos de identidade, fotos, saúde
autodeclarada dos flats, views de documentos, heartbeats da rádio) confirmando base legal, acesso
restrito e retenção configurada.
```
