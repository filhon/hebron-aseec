# Patch — P-7.6 (Schema do Banco Flats)

**Motivo:** CS-3 (número — ver `migracoes-numeracao.md`); o critério "double-booking prevention por
unit+period" não diz o mecanismo — executor literal (G1) tende a criar UNIQUE inútil para ranges;
especificar `EXCLUDE USING gist` com `daterange` + extensão `btree_gist`. PII/saúde precisam de
anotação de acesso restrito (CS-9). CS-4 (valores de audit do módulo).

---

## Escopo

### ANTES (trecho)

```
Criar tabelas no schema `flats`: units (2 fixas, seed), reservations (status, selected_period,
score_total), preferred_periods (reservation_id, start, end), guests (reservation_id, name, cpf,
birth_date, is_responsible), vehicles (reservation_id), scoring_responses (reservation_id,
criterion, value, points), aid_requests (reservation_id, type, amount), usage_history (para regra
de 7 dias/12 meses).
```

### DEPOIS

```
Criar tabelas no schema `flats`: units (2 fixas, seed), reservations (status, selected_period como
daterange, score_total), preferred_periods (reservation_id, period daterange — 3 por reserva),
guests (reservation_id, name, cpf, birth_date, is_responsible — PII: acesso restrito a gestor/
super_admin via RLS), vehicles, scoring_responses (reservation_id, criterion, value, points — o
critério d/saúde é dado sensível: coluna própria com acesso restrito e coleta condicionada a
consentimento, P-7.4), aid_requests (reservation_id, type, amount), usage_history (user_id,
reservation_id, days_used, period — regra 7d/12m), document_files (referência ao bucket
flats-documentos).

Double-booking: CREATE EXTENSION IF NOT EXISTS btree_gist; constraint
EXCLUDE USING gist (unit_id WITH =, selected_period WITH &&) em reservations, aplicável apenas a
status que ocupam o flat (aprovada/confirmada/em_curso — usar WHERE na constraint).

Auditoria central: incluir ALTER TYPE admin.audit_action ADD VALUE IF NOT EXISTS para os valores
do módulo (reservation.submitted/approved/rejected/checked_in/checked_out, aid.requested/approved)
— G6.3.
```
