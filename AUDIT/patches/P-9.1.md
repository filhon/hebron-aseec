## Escopo

### ANTES

```
Auditoria completa de RLS em todos os schemas. Verificar: DENY-by-default em toda tabela.
Cross-schema leaks (submissor não acessa financeiro). Impersonation não bypassa RLS. Conflitos de
interesse enforced (diretor não cria reserva). Middleware gates alinhados com RLS. Revisão de
signed URLs (expiração, escopo). Verificação de SQL injection em queries dinâmicas. **Decidir e
documentar a postura de conexão das Server Actions** (superuser via `DATABASE_URL` vs.
`authenticated` + JWT) — ver BRAIN.md §3 "Decisão técnica pendente"; se ficar com superuser,
confirmar que TODA action de mutação passa pelo gate de RBAC (nenhuma exceção).
```

### DEPOIS

```
Auditoria completa de RLS e permissões no estado final (decisão B implementada em P-0.10 — este
prompt VERIFICA, não decide). Verificar: DENY-by-default em toda tabela de todos os schemas
(inclusive tarefas/intranet/plataforma/flats/radio criados nas fases 4–8). GRANTs por schema
alinhados às policies — nenhum GRANT mais largo que a policy correspondente. Nenhuma leitura ou
escrita remanescente via DATABASE_URL superuser em páginas/actions (grep + teste). Cross-schema
leaks (submissor não acessa financeiro; busca global e feed respeitam RLS). Impersonation não
bypassa RLS nem confere autoridade (cookie assinado — F3-13, se corrigido; senão, corrigir aqui).
Conflitos de interesse enforced em RLS (diretor não cria reserva; diretor≠submissor). Gates de
layout (G5) alinhados com RLS. Signed URLs: expiração e escopo (R2, Storage). SQL injection em
queries dinâmicas (busca, filtros).
```
